# Proposed v0.1.0-pre-alpha.1 Release Notes

**Status:** Proposed; not tagged and not published.

Hydra Core remains pre-v1. Hydra Quant is preparing for a private alpha. Initial external access is planned as invite-only and read-only, with `SHADOW` operating mode and forward-shadow evidence; public-user broker connection, order submission, and live execution remain disabled.

## Governance Changes

- establishes one dated Markdown and JSON public posture with staleness behavior
- separates durable architecture, current public posture, historical ledger, and evidence claims
- registers approved public surface classifications
- defines the planned private-alpha and conceptual Control Room contracts
- formalizes five non-combinable evidence tiers
- migrates from a flat state list to independent trust, permission, lifecycle, and mode axes
- expands failure modes and adds a public threat model
- preserves legacy ledger history while defining prospective structured V1 records
- adds repository security, contribution, template, validation, and CI policy

## What Did Not Change

- no private strategy code, parameters, model features, execution wiring, accounts, or logs were published
- no performance claim or profit guarantee was introduced
- no public-user execution capability was enabled
- no shadow-to-demo or live progression was promised
- no tag, GitHub release, merge, or auto-merge action was performed

## State-Model Migration

Readers and future implementations must replace a single mixed state label with a scoped tuple:

- trust: `SAFE | DEGRADED | AMBIGUOUS | UNSAFE`
- permission: `ARMED | DISARMED`
- lifecycle: `NORMAL | RECOVERY_REQUIRED`
- mode: `OBSERVE_ONLY | SHADOW | DEMO | LIVE`

`SAFE + ARMED` is no longer sufficient wording. Lifecycle, configured mode, every required gate, scope, and higher-layer restrictions also apply. Missing state fails closed. Clearing recovery and rearming are separate decisions.
